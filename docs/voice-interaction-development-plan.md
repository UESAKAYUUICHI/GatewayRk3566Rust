# RK3568 语音交互能源网关开发方案

> 版本：v1.0  
> 编写日期：2026-09-18  
> 适用项目：`GatewayRk3566Rust`  
> 目标设备：Rockchip RK3568 KICKPI K1A / K1 MINI 系列 Ubuntu arm64 开发板

## 1. 项目目标

在现有能源网关基础上增加语音交互能力，使设备能够完成：

1. 通过外接麦克风接收语音。
2. 识别唤醒词，例如“你好小关”。
3. 播放唤醒反馈：

   > 我在，祝您有美好的一天，请问需要什么帮助？

4. 识别用户的设备查询请求。
5. 查询网关本地真实采集数据、设备状态、告警和上报记录。
6. 对查询结果进行统计和自然语言总结。
7. 将回答转换为语音，通过外接耳机或音箱播放。
8. 后续支持告警自动语音播报。
9. 后续可选接入 Live2D 或轻量二维数字人界面。

第一阶段的核心目标是跑通：

```text
麦克风输入
  -> 唤醒
  -> 语音识别
  -> 网关数据查询
  -> 结果总结
  -> 语音合成
  -> 耳机/音箱播放
```

## 2. 设计原则

### 2.1 不破坏现有网关主链路

语音功能不得阻塞或修改以下现有业务：

- RS485/Modbus RTU 采集
- 多设备挂载与设备地址管理
- SQLite 本地采样和历史数据
- Outbox 数据上报
- MQTT 心跳、数据上报和平台下发
- 当前 Web UI 和 kiosk 浏览器
- 摄像头测试功能

语音功能作为独立能力接入，通过本地 HTTP API、WebSocket 或 Unix Socket 与网关服务通信。

### 2.2 事实由网关和数据库提供

语音模型不能直接猜测设备数据。正确分工是：

```text
网关后端：查询真实数据并计算统计结果
AI 模型：理解用户意图、组织自然语言
TTS：将最终文字转换成语音
```

例如“查看 325 电表这一周运行状况”应先由后端统计：

- 采集次数
- 采集成功率
- 平均、最大、最小有功功率
- 累计正向有功电能
- 平均功率因数
- 通信中断次数
- 告警次数
- 数据质量异常次数

模型只负责把结构化结果转换成易理解的回答。

### 2.3 本地优先、云端增强

建议采用：

- 本地完成唤醒词检测
- 云端完成第一版中文 ASR
- 网关本地完成数据查询和统计
- 云端完成复杂自然语言总结
- 云端或本地完成 TTS

网络中断时，至少保留本地状态播报和“语音服务暂不可用”提示。

## 3. 硬件方案

### 3.1 推荐方案：USB 音频设备

第一阶段使用 Linux USB Audio Class 免驱设备：

```text
USB 麦克风/USB 外置声卡
  -> 麦克风输入
  -> 语音识别

USB 外置声卡
  -> 3.5mm 耳机或音箱输出
  -> TTS 播放
```

可选硬件：

- USB 外置声卡，带麦克风输入和 3.5mm 耳机输出
- USB 会议麦克风
- USB 麦克风 + USB 音频转接器
- USB 麦克风/扬声器一体设备

优先选择免驱、标准 UAC/UAC2 设备。不要第一阶段就改板载音频设备树。

### 3.2 板端验证命令

插入设备后验证：

```bash
arecord -l
aplay -l
arecord -L
aplay -L
```

录音测试：

```bash
arecord -D default -f cd -d 5 /tmp/voice-test.wav
aplay /tmp/voice-test.wav
```

若默认设备不正确，使用具体的 ALSA 设备名：

```bash
arecord -D plughw:<card>,<device> -f cd -d 5 /tmp/voice-test.wav
aplay -D plughw:<card>,<device> /tmp/voice-test.wav
```

### 3.3 音频参数建议

第一版建议：

| 参数 | 建议值 |
|---|---:|
| 采样率 | 16 kHz |
| 声道 | 单声道 |
| 格式 | 16-bit PCM |
| 唤醒帧长度 | 20-30 ms |
| 识别录音时长 | 1-10 s |
| 播放格式 | 16-bit PCM 或 WAV |

工业现场存在风扇、继电器、电表柜和电源噪声，应预留：

- 自动增益
- 降噪
- 回声抑制
- 语音端点检测
- 麦克风音量和播放音量独立配置

## 4. 软件总体架构

### 4.1 推荐新增独立语音代理

建议增加独立进程 `voice-agent`，不要把录音和 AI 调用直接塞进 `gateway-web` 的请求线程。

```text
┌──────────────────────────────────────────────┐
│ gateway-web / gw-agent                       │
│                                              │
│ RS485 采集 · SQLite · Outbox · MQTT · Web UI │
└───────────────────▲──────────────────────────┘
                    │ 本地 HTTP / Unix Socket
┌───────────────────┴──────────────────────────┐
│ voice-agent                                  │
│                                              │
│ ALSA录音 -> 唤醒词 -> ASR -> 意图解析        │
│       -> 调用网关查询 -> 结果总结 -> TTS播放 │
└──────────────────────────────────────────────┘
```

### 4.2 voice-agent 模块划分

建议结构：

```text
voice-agent/
├─ audio/
│  ├─ capture      # ALSA 麦克风采集
│  ├─ playback     # ALSA 耳机/音箱播放
│  └─ preprocess   # 重采样、降噪、音量处理
├─ wakeword/
│  └─ detector     # 本地唤醒词检测
├─ asr/
│  └─ client       # 云端或本地语音识别
├─ intent/
│  ├─ parser       # 查询意图解析
│  └─ schema        # 结构化命令定义
├─ gateway/
│  └─ client       # 调用网关 API
├─ answer/
│  └─ summarizer   # 统计结果转回答文本
├─ tts/
│  └─ client       # 语音合成
└─ state/
   └─ machine      # 空闲、唤醒、识别、回答、错误状态
```

## 5. 语音状态机

```text
IDLE
  │ 检测到唤醒词
  ▼
AWAKE
  │ 播放“我在”
  ▼
LISTENING
  │ 检测到说话结束
  ▼
RECOGNIZING
  │ ASR成功
  ▼
UNDERSTANDING
  │ 识别为网关查询
  ▼
QUERYING
  │ 查询和统计完成
  ▼
ANSWERING
  │ TTS播放完成
  ▼
IDLE
```

错误状态：

- `AUDIO_UNAVAILABLE`：找不到麦克风或播放设备
- `WAKEWORD_TIMEOUT`：唤醒后用户没有继续说话
- `ASR_UNAVAILABLE`：语音识别服务不可用
- `INTENT_UNSUPPORTED`：暂不支持该问题
- `GATEWAY_API_UNAVAILABLE`：网关服务不可用
- `TTS_UNAVAILABLE`：语音合成失败

## 6. 唤醒词方案

### 6.1 第一阶段

先使用轻量本地唤醒方案，避免持续上传麦克风音频：

- openWakeWord
- Porcupine
- sherpa-onnx 关键词模型
- 轻量自定义关键词模型

“你好小关”属于自定义中文唤醒词，第一版可以先用：

1. 本地关键词模型；
2. 或固定短语 ASR 兜底；
3. 或先使用预训练中文唤醒词验证整体链路。

### 6.2 唤醒后的隐私边界

默认行为：

- 未唤醒时只在本地处理短音频帧。
- 不保存连续环境录音。
- 唤醒后才录制完整请求。
- 请求识别完成后立即删除临时音频。
- 是否上传云端由配置项控制。

建议配置：

```toml
[voice]
enabled = false
wakeword = "你好小关"
asr_provider = "cloud"
tts_provider = "cloud"
save_audio = false
listen_timeout_s = 8
```

## 7. ASR、意图和 TTS

### 7.1 ASR

第一版使用云端中文 ASR，原因：

- 中文普通话准确率更高
- 更容易识别“325 电表”“RS485-1”等项目术语
- RK3568 不需要长期运行大型 Whisper
- 开发和调试速度更快

接口抽象必须保留本地实现空间：

```text
trait SpeechRecognizer {
    recognize(audio: AudioBuffer) -> Result<Transcript>
}
```

后续可以替换为：

- Vosk
- sherpa-onnx
- whisper.cpp
- 厂商 ARM ASR SDK

### 7.2 意图定义

第一版不要让大模型直接生成任意数据库查询，先定义受控意图：

```json
{
  "intent": "DEVICE_WEEKLY_STATUS",
  "device": "325电表",
  "deviceSn": null,
  "period": "THIS_WEEK",
  "needSummary": true
}
```

首批支持的意图：

| 意图 | 示例 |
|---|---|
| 查询当前功率 | “325 电表现在功率多少” |
| 查询当前测点 | “查看 325 电表实时数据” |
| 查询日运行情况 | “查看今天 325 电表运行状况” |
| 查询周运行情况 | “帮我查看一下这一周 325 电表运行状况” |
| 查询设备告警 | “325 电表最近有告警吗” |
| 查询采集状态 | “RS485-1 当前正常吗” |
| 查询上报状态 | “最近有没有上报成功” |
| 查询网关状态 | “网关网络和平台链路正常吗” |

无法匹配时，语音回复可用范围，而不是执行不受控操作。

### 7.3 TTS

第一版优先云端 TTS，返回 WAV/PCM 后通过 ALSA 播放。

TTS 播放队列需要支持：

- 普通回答
- 唤醒反馈
- 告警播报
- 播放中断
- 高优先级告警插队
- 静音时间段

## 8. 网关查询接口

语音代理优先调用现有 API，不直接读 SQLite 文件。

现有可复用接口：

```text
GET /api/v1/snapshot
GET /api/v1/meters
GET /api/v1/collection/history
GET /api/v1/events
GET /api/v1/uploads
GET /api/v1/channels
GET /api/v1/system/environment
```

建议新增统计接口：

```text
GET /api/v1/voice/devices/{device}/summary?period=week
GET /api/v1/voice/devices/{device}/trend?period=week
GET /api/v1/voice/devices/{device}/alarms?period=week
GET /api/v1/voice/gateway-status
```

周运行状况建议由后端返回结构化结果：

```json
{
  "deviceSn": "WZBC-LS2-M-325",
  "deviceName": "325电表",
  "from": "2026-09-11T00:00:00+08:00",
  "to": "2026-09-18T23:59:59+08:00",
  "sampleCount": 12096,
  "validRate": 99.7,
  "averagePowerKw": 12.18,
  "maxPowerKw": 18.46,
  "minPowerKw": 4.12,
  "energyKwh": 1942.7,
  "alarmCount": 2,
  "communicationInterruptions": 1
}
```

## 9. 告警语音播报

告警链路：

```text
采集/平台告警
  -> 本地事件归一化
  -> 告警去重和冷却
  -> 生成告警文本
  -> TTS
  -> 播放队列
```

示例：

```text
警告，325 电表总有功功率异常，当前值 38.6 千瓦，超过设定阈值。
```

```text
警告，326 电表通信中断，请检查 RS485-1 通道和现场线路。
```

必须实现：

- 同一告警冷却时间
- 连续告警合并
- 告警级别
- 播放队列
- 高优先级告警插队
- 静音时间段
- 前端告警与语音状态同步
- 语音播报失败的日志记录

## 10. Live2D 后续方案

Live2D 不进入第一阶段验收范围，作为第二阶段可选功能。

当前前端是 Chromium kiosk，后续可以通过 WebGL 页面增加：

- 待机动画
- 唤醒动作
- 说话口型
- 告警表情
- 语音状态动画

性能限制：

- 限制模型纹理分辨率
- 限制动画帧率
- 避免摄像头画面和 Live2D 同时高负载
- 避免多个 WebGL Canvas 并行运行
- GPU 异常时提供静态头像降级

Live2D 的状态可以由 `voice-agent` 通过 WebSocket 推送：

```text
idle
wake
listening
thinking
speaking
warning
error
```

## 11. 安全与隐私

语音模块涉及麦克风和云端 API，必须增加：

- API 密钥放入权限为 `0600` 的配置文件
- 不在前端暴露 ASR/TTS 密钥
- 默认不保存原始录音
- 录音临时文件使用 `/run` 或受控临时目录
- 请求结束后删除音频
- 限制语音代理监听地址为 `127.0.0.1`
- 记录调用耗时和错误，不记录完整敏感音频
- 支持关闭语音功能
- 支持关闭云端上传

## 12. 性能预算

| 项目 | 目标 |
|---|---:|
| 唤醒常驻 CPU | 尽量低于 10% |
| 语音代理常驻内存 | 小于 150MB |
| 唤醒响应时间 | 小于 1.5s |
| ASR 请求开始 | 用户说完后 1s 内 |
| 网关统计查询 | 2s 内 |
| TTS 首包 | 3s 内 |
| 普通回答总延迟 | 8s 内 |
| 采集线程影响 | 不阻塞 RS485 轮询 |
| 网络断开 | 不导致网关主进程退出 |

## 13. 分阶段开发计划

### M1：音频硬件和 ALSA

- 接入 USB 音频设备
- 验证 `arecord` 和 `aplay`
- 完成录音、播放测试
- 确认设备重启后名称稳定
- 增加音频设备诊断信息

### M2：本地唤醒

- 集成轻量唤醒引擎
- 实现空闲监听状态
- 实现“你好小关”唤醒
- 播放唤醒确认语
- 增加误唤醒和超时处理

### M3：ASR/TTS 云端链路

- 抽象 ASR provider
- 抽象 TTS provider
- 增加超时、重试和网络错误处理
- 完成语音输入到语音输出的普通对话

### M4：网关数据查询

- 增加设备周统计后端接口
- 增加告警、采集、上报状态查询
- 增加受控意图解析
- 完成“查看 325 电表本周运行状况”

### M5：告警播报

- 接入本地事件和平台告警
- 增加告警去重和冷却
- 增加语音优先级和播放队列
- 完成故障语音提示

### M6：Live2D 可选接入

- 增加前端语音状态 WebSocket
- 加入轻量 Live2D 或静态头像
- 实现口型和状态动画
- 完成 GPU/CPU 降级策略

## 14. 验收标准

### 音频

- 插入 USB 设备后能识别麦克风和播放设备。
- 录音 5 秒后能正常回放。
- 播放时无明显爆音、持续杂音或卡顿。

### 唤醒

- 能识别“你好小关”。
- 唤醒后能在 1.5 秒内播放确认语。
- 未唤醒状态不上传完整环境录音。

### 数据查询

- 能识别设备名称和设备编号。
- 能查询当前实时测点。
- 能查询日、周运行统计。
- 回答中的功率、电能、告警次数与网关页面/数据库一致。

### 告警

- 模拟告警能触发语音播报。
- 相同告警不会无限重复播放。
- 通信中断能播报设备、通道和错误原因。

### 稳定性

- `voice-agent` 异常不会影响 `park-gateway.service`。
- 网络断开后网关采集和本地数据保存不停止。
- 语音服务失败可以自动重启。
- 连续运行 24 小时无明显内存增长。

## 15. 首阶段不做的内容

以下内容暂不纳入第一阶段：

- Live2D 数字人
- 本地大型 Whisper 模型
- 任意自然语言控制设备
- 语音直接修改采集配置
- 语音下发危险控制命令
- 持续保存环境录音
- 复杂多轮对话记忆

第一阶段只实现“查询和播报”，不实现通过语音直接控制现场设备，避免误操作和工业安全风险。

## 16. 结论

该功能在当前 RK3568 网关上可实现。推荐路线是：

```text
USB 音频设备
  + 本地唤醒
  + 云端中文 ASR
  + 网关真实数据查询
  + 后端统计
  + 云端总结
  + TTS 播放
```

第一阶段的关键不是数字人界面，而是确保语音回答引用的每个数据都来自真实采集、真实数据库和真实上报链路。Live2D 应在语音链路稳定后再接入。
